## Codebase Patterns
- Zod v4 (4.3.6) is installed, use `import { z } from 'zod'` (not zod/v4)
- @hono/zod-openapi@1.2.2 supports Zod v4 peer dependency
- Schemas dir: `src/schemas/` — `index.ts` has legacy placeholder, `api-schemas.ts` has API schemas
- DB user fields: id, email, username, firstName, lastName, role (camelCase in Drizzle, snake_case in DB)
- Auth: `AuthManager` class in `src/middleware/auth.ts`, also exports `requireAuth`
- Routes pattern: export Hono instances from `src/routes/*.ts`, re-export from `src/routes/index.ts`
- CORS already applied on `/api/*` routes in `api.ts`
- OpenAPI factory: `createOpenAPIApp()` in `src/routes/openapi-app.ts`, exports `openAPIDocInfo` and `openAPITags`
- Security schemes registered via `app.openAPIRegistry.registerComponent('securitySchemes', name, config)`
- Protected routes: apply `requireAuth()` with `app.use('/path', requireAuth())` BEFORE `app.openapi()`, add `security: [{ bearerAuth: [] }]` to route definition
- JWT payload from `requireAuth()`: `{ userId, email, role }` — query DB for full user profile
- 3 pre-existing TS errors (ai-search-plugin, admin-design.template) — not blocking
- Build tool: tsup, typecheck: `tsc --noEmit`, tests: `npx vitest --run`
- OpenAPI route pattern: use `createRoute()` + `app.openapi(route, handler)` — handler gets typed `c.req.valid('json')` for free
- Converting Hono → OpenAPIHono is a drop-in replacement; can mix `.get()` and `.openapi()` routes on the same instance
- For protected `.openapi()` routes: register `app.post('/path', requireAuth())` BEFORE `app.openapi(route, handler)` to chain middleware
- Query params: use `z.coerce.number()` for int params (handles string→number); handler can still use `c.req.query()` for raw access
- Sub-routers need their own `registerComponent('securitySchemes', 'bearerAuth', ...)` if routes reference bearerAuth
- Cast D1 `.first()` result with inline type literal for type-safe field access without a separate interface
- Token endpoint returns `token_type: 'Bearer' as const` to satisfy literal type in schema
- Zod v4: `z.record()` requires 2 args: `z.record(z.string(), z.unknown())`
- Zod v4: `z.unknown().nullable()` is invalid — `z.unknown()` already includes null
- Always use explicit status codes in `.openapi()` handlers: `c.json(data, 200)` not `c.json(data)`
- Multipart/form-data in OpenAPI route: schema is for spec only; handler still uses `c.req.formData()` for runtime access
- Media table columns are snake_case (original_name, mime_type, r2_key) — map to camelCase in API responses
